# Gesture Manager Pro

A standalone Unity/VPM avatar testing toolkit maintained by VRCLearn. It derives its simulator from [Gesture Manager](https://github.com/BlackStartx/VRC-Gesture-Manager) 3.9.9 and embeds the simulator in this package. **Installing the original Gesture Manager package is not required.**

This is an initial development build for Unity 2022.3 and VRChat Avatars SDK 3.10.x. The default repository branch is `main`.

## Features

- Avatar animation layers, expression menus, parameters, debugging, contacts, and other simulator tools inherited from Gesture Manager.
- English, Japanese, Korean, Traditional Chinese and Simplified Chinese interfaces with a persistent language preference and live switching, implemented directly in source.
- VRChat SDK model statistics with 31 metrics, PC/Mobile performance ratings, independent before-processing statistics, and processed snapshots aligned with Actual Performance Window.
- Microphone lip sync during Game Simulation with a bundled Windows x86_64 OVRLipSync recognizer, mapping diagnostics, blended viseme weights, and restoration when simulation stops.
- An explicit Game Simulation mode that starts in first person, with optional third-person and Scene Camera observer views, observer following, mouse look, WASD movement, comma/period (`<`/`>`) turning, Shift running, C crouch, Z prone, optional collisions, automatic gravity and grounded Space jumping. Game and Scene views share avatar controls; F5 toggles third-person mode and the wheel adjusts its distance. Scene camera navigation remains available.
- MMD station simulation in **Extra Tools**, using an optional user-provided Unity AnimationClip, looping playback, and selectable Gesture/FX layer controls. An empty animation tests station behavior without adding a dance. See [MMD Simulation](https://github.com/VRCLearn/Gesture-Manager-Pro/blob/main/.github/docs/MMD-SIMULATION.md) for the preset and world-specific differences.
- Android shader restriction preview uses the installed SDK's avatar shader allowlist. Unsupported materials display in pink for diagnosis, and Toon Standard's outline variant previews without outlines. Source materials remain unchanged.
- Optional SteamVR headset/controller input, three- to eleven-point body tracking, mixed OSC trackers, calibration, Humanoid IK, and a headset expression menu inside Game Simulation. The SteamVR integration and controller bindings are included in GMP; Valve's OpenVR plugin is installed only when VR support is requested. The independent body solver is not a claim of VRChat client parity. See [VR setup and comparison status](VR-SIMULATION.md).

## Install and use

1. Create or open a Unity 2022.3 avatar project with VRChat Avatars SDK 3.10.x.
2. Open the [VPM installation page](https://vrclearn.github.io/Gesture-Manager-Pro/) and click **Add to VCC/ALCOMD**, or add `https://vrclearn.github.io/Gesture-Manager-Pro/index.json` manually. Install **Gesture Manager Pro** (`com.vrclearn.gesture-manager-pro`) in the project's package manager. VRChat Avatars SDK is resolved from the official VRChat repository; the original Gesture Manager is not a dependency.
3. Use **Tools > Gesture Manager Pro** to add an emulator, enter Play Mode, and select the emulator in the Inspector so it initializes an avatar.
4. In the initialized emulator Inspector, select the **Tools** tab and expand **Game Simulation** beside **Scene Camera**, **Clickable Contacts** and **Pose Avatar**. Configure it in place, then click **Enter Game Simulation**. The Game view starts in **First Person**; select **Scene Camera** in **View** or enable the **Scene Camera** tool to enter the observer. The normal GM inspector and Scene Camera tools remain available outside the mode. In either focused Game or Scene view, use WASD to move, comma/period to turn, **Shift** to run forward/backward, **C** to toggle crouch and **Z** to toggle prone. **Space** jumps when Scene Collisions is enabled and the avatar is grounded. In the Game view, **F5** toggles third-person mode. Observer views remain in place by default; enable **Follow Avatar in Observer View** to move them with the avatar. If no supporting ground collider is detected, simulation creates an invisible temporary 100-by-100-meter ground collider at the avatar's starting foot height. Existing supporting scene ground is reused. Gravity and jumping are automatic while Scene Collisions is enabled; there is no separate gravity setting.
5. **Microphone Lip Sync** is enabled by default inside **Game Simulation**. Select the microphone and adjust analysis gain/noise floor there, or disable it before starting. Recording starts and stops with the simulation; microphone audio is never monitored through the speakers. Microphone failure shows a warning while movement remains available. Collapsing the tool or switching tabs preserves the session; pause, Play Mode exit and avatar disconnection release recording and restore mouth/speech state. The analyzer currently requires the Windows x86_64 editor. The radial menu's **Tools > Game Simulation** toggle shares these settings and the running state; configure them in the Inspector's **Tools** tab.
6. To use VR in the Windows Editor, select the GMP emulator outside Play Mode, click its Inspector's gear icon, expand **VR Setup** in **Settings**, and click **Enable VR** once. GMP installs the required dependencies and configures input and XR startup for the project. If prompted, save your work and restart Unity once. Then connect the headset to the desktop SteamVR application and select **VR (SteamVR)** in **Game Simulation**. PC controls remain available. No separate GMP adapter download, initialized avatar or connected headset is required during setup. See [VR setup](VR-SIMULATION.md) for details.
7. Outside Play Mode, open the emulator Inspector's gear settings and use the **Language** selector. Automatic follows the operating system's UI culture: Japanese and Korean select their respective translations, Chinese script/region selects Simplified or Traditional Chinese, and other languages use English. Parameter identifiers, user expression names and avatar names keep their original text. Expand **About and Contributors** in the same settings to view the version, project links and contributor list.
8. Click **Model Statistics** beside **Enter Play Mode** in the emulator Inspector. Choose an avatar and platform. The window can remain open during Play Mode. Use **Measure Before Processing** outside Play Mode, or **Measure Current Play Mode State** during Play Mode. Select a **Processing Stage** and **Recorded Snapshot** to compare observations; **All Avatars** also exposes history for processed runtime clones. The latest 48 records are retained for the Editor session, including across domain reloads.
9. For MMD testing, enter Play Mode with an initialized, unpaused avatar and open **Tools > Extra Tools > MMD Simulation**. Assign **Animation (optional)** or leave it empty, choose **Loop** and the layer controls, then click **Enter MMD Simulation**. **Exit and Restore** ends the session; pausing, leaving Play Mode or resetting the avatar also restores its controlled state. Stop Game Simulation, Pose Avatar or Test Animation before starting. Import your own Unity AnimationClip; the tool does not import VMD/PMX files or download music or motions.
10. With Android as the active build target, shader restrictions start enabled for the connected avatar in Play Mode, including paused camera previews. Open **Tools > Extra Tools > Android Shader Preview** to toggle **Restrict Unsupported Shaders** and inspect affected materials. The preview also covers the simulator's remote clones and animation-test avatar. Material references are overridden only during camera rendering and restored afterwards; source materials, animation assets and material property blocks are preserved.

The Inspector, radial menu, debug windows and Model Statistics use language-specific system font chains, following the approach used by NDMF's editor localization. Regular faces and synthetic bold keep localized body text and headings consistent without sharing Unity's default alternate-weight cache. Candidate families for Japanese, Korean and both Chinese scripts are listed in `Resources/GestureManagerPro/EditorFontPreferences.txt`; unavailable families are skipped, and the editor default remains available if none can be loaded. Font resources are cached by language, preserved across Play Mode and rebuilt if invalidated. The inline runtime tools use the inherited Inspector's IMGUI theme. No NDMF dependency or font binary is added.

Before-processing statistics are an independent feature for inspecting the model before optimizers or build processors run. They remain available alongside the processed observations:

| Stage | Capture point |
| --- | --- |
| **Before Processing** | Manual Edit Mode scan, the transition out of Edit Mode, or the original avatar at SDK build start. Earlier transition callbacks may already have changed the model during the Edit Mode transition. |
| **After Play Mode Processing** | First Editor update in Play Mode, following the same sampling timing as [Actual Performance Window](https://vpm.anatawa12.com/gists/en/docs/reference/actual-performance-window/). Includes processing completed before this callback. |
| **After SDK Processing** | Last-priority SDK preprocessing callback. A matching successful SDK build adds download and uncompressed sizes for its actual platform; other metrics exclude later SDK processing. |
| **Current Play Mode State** | Manual scan of the current running model, including simulator and other runtime changes. |

Processed records use the same SDK calculator and metric/rating semantics as Actual Performance Window. Bounds show the SDK's center and extents; constraint depth uses the value the SDK returns. Download size comes from the successful build's bundle file, and uncompressed size comes from the matching build report through the SDK's size check. These two metrics are filled only in the matching **After SDK Processing** record for the actual build platform. Build through the SDK, then select that stage and platform to view them. Before-processing and Play Mode records have no bundle size measurements; an unavailable build report leaves uncompressed size unknown. Texture memory and the two size metrics use two-decimal MB values. Unknown values retain their SDK ratings. Records from older versions remain in **Legacy Snapshots** with their original source data rather than being relabeled as newly processed results.

Overall and individual ratings display the VRChat SDK's performance icons, as in Actual Performance Window, alongside readable labels. Chinese labels preserve the SDK's grade meanings (优秀, 良好, 中等, 较差, 极差 in Simplified Chinese); these grades do not represent measured frame rates. An unrated result displays **Not Rated** with the native 32x32 high-resolution version of the Unity help/question-mark icon used by the SDK. A private copy uses smooth filtering at scaled display sizes and stays aligned with the other ratings. The icons come from the existing SDK and Unity Editor; no copied icon assets or additional package are required.

Automatic observations record both PC and Mobile ratings for the same model state. Switching platforms in the window changes SDK rating thresholds, without changing imported assets or the project's build target. SDK records identify the actual build platform, and a successful bundle's download and uncompressed sizes are shown only for that platform; the other rating is not a second platform build. Model Statistics does not launch extra builds or rerun optimizers. SDK build success does not confirm upload, complete final compiled statistics, or measured client FPS. Real avatar optimizer combinations still require their own validation.

Starting with 0.1.1, VPM installation and updates automatically remove the original `vrchat.blackstartx.gesture-manager` package through `legacyPackages`. Before switching, remove the original GM emulator GameObject from your scene, then add a Pro emulator using step 3. The package declaration does not convert existing GM components or their settings; otherwise those components reference missing scripts after removal. A manually imported original GM under `Assets` must be removed manually. UnityPackage and direct UPM installations do not process this VPM replacement declaration.

In the Game view's **First Person** or **Third Person** mode, click the view or use **Resume Input**, then release all control keys and mouse buttons to enable mouse look and capture. Press **Esc** to release the captured mouse and suspend input. The **Scene Camera** observer mode keeps the mouse free and accepts keyboard controls without capture. In the Scene view, holding **Alt** or the **right/middle mouse button** suspends avatar input and preserves Scene camera navigation. Release control keys after navigating or changing focus before resuming avatar control. Losing focus or blocking locomotion stops movement immediately. Click **Exit and Restore** to return to normal GM testing. Viewpoint, third-person distance, sensitivity and speed can be adjusted while the mode is running. First person uses the descriptor's local View Position; to prevent face meshes obscuring the view, it hides the entire local avatar only while this camera renders. Scene/other cameras and third person still show the avatar. Client-style head clipping and visible first-person body/arms are not implemented.

**F5** enables third-person mode at the last positive camera distance; pressing it again disables the mode and returns to first person. While the mode is enabled and Game-view input is captured, scroll the wheel forward to move closer and backward to move farther away. Reaching zero distance shows first person while keeping third-person mode enabled, so scrolling backward returns to third person. After F5 disables the mode, the wheel cannot enable it again. **Third-Person Distance** accepts 0–6 avatar heights; zero returns to first person. Alt/Ctrl/Cmd wheel combinations remain available for other controls; Shift plus wheel can zoom, while Shift+F5 does not toggle views. Scene-view F5, V and wheel input remain available to the editor. See the [compatibility notes](https://github.com/VRCLearn/Gesture-Manager-Pro/blob/main/.github/docs/GAME-SIMULATION-PARITY.md) for the official behavior references and camera limitations.

In a captured Game-view third-person camera, **Tab** enters free rotation: mouse movement orbits the camera while the avatar keeps its heading. Repeated Tab presses preserve the current orbit. While free rotation is active, **A/D** turns the avatar in place and **< / >** rotates only the camera; a new **W/S** press aligns the avatar with the camera heading and resumes forward/backward movement. Holding W/S before pressing Tab lets movement continue while freely observing. Pitch, zoom, collisions and jumping continue to work. First person, observer mode and exiting simulation clear free rotation. Esc/focus loss suspend input without recentering the orbit; Scene-view Tab and the usual Scene avatar controls remain available.

For Humanoid avatars, PC **Head = Tracking** aligns the head with the player's view, including a level view. Imported Humanoid reference axes keep animated head and torso rotations from being added to the viewing angle. **Head = Animation** and the editor's explicit Pose Avatar mode retain the authored pose. Free camera rotation preserves the avatar's previous head pitch. SDK locomotion locking keeps vertical look available while blocking movement and turning. Animation evaluation and ending simulation release the previous tracking override without resetting body animation. This local head preview does not reproduce the VRChat client's complete body IK.

PC **Temporary Pose Space** captures a viewpoint when the SDK behaviour executes and keeps it until another Enter or Exit. It preserves the descriptor-to-reference-head offset and never edits the descriptor. Pose Space alone does not disable movement or head tracking: combine it with **Locomotion Control** or **Head = Animation** when the animation requires those restrictions. Fixed/proportional delays and interrupted-state handling use the SDK behaviour. The client's exact viewpoint offset formula and VR Pose Space behaviour remain unverified.

The regular **Scene Camera** tool temporarily synchronizes the selected Game camera with the Scene view. Disabling it or selecting another target restores the camera's original local position, rotation and projection settings. Unlinking the last emulator, changing Play Mode or reloading scripts also releases the camera override and resets the switch to disabled for the next session.

**Clickable Contacts** also starts disabled with an empty tag filter for each new connection. The switch and tag belong to the current tool instance. Disabling the tool or disconnecting releases held contact parameters; old saved preferences are no longer used.

During Game Simulation, the **Scene Camera** switch and the **View** selector control the same displayed view. Enabling the switch enters the observer; disabling it returns to the previous first-/third-person state, or first person if no player view has been selected yet. The switch also reflects F5 and View changes. Simulation leaves the regular camera selection and its current session state intact. The observer mirrors the Scene view's position and projection in a temporary Game camera, using the previously selected camera when no Scene view is available. **Follow Avatar in Observer View** is off by default and can be changed during simulation. When enabled, it translates the Scene view and its Game-view observer camera by the avatar's actual movement; rotation, zoom and manual navigation remain under your control. Disabling following leaves the observer at its current position without catching up on earlier movement. On exit, only the translation applied by the session is removed, preserving your manual pan, rotation and zoom. First- and third-person cameras retain their own avatar following.

Player views use a perspective camera with their own projection settings when leaving the observer, including after using an orthographic Scene view. Third person orbits the body axis at the descriptor viewpoint's world height. It uses the avatar root's X/Z, respects scale and parent transforms, and adds no vertical offset. Mesh geometry, accessories and renderer bounds do not determine camera height. Collision avoidance shortens that same camera path. First person retains the descriptor's complete viewpoint. The client's configurable horizontal/vertical offsets and complete third-person camera behavior remain unsupported.

Default movement uses 2 m/s walking and strafing, 4 m/s forward/backward running, and horizontal acceleration/deceleration of 10.5 m/s². Shift does not increase strafe speed. Jump impulse defaults to 3 m/s, independently of avatar height, matching the default VRCWorld prefab rather than every world's configuration. Movement preserves the GM Inspector's `VRMode`, `TrackingType` and manually selected `Upright`; C/Z change `Upright` only when pressed. See the [Game Simulation compatibility notes](https://github.com/VRCLearn/Gesture-Manager-Pro/blob/main/.github/docs/GAME-SIMULATION-PARITY.md) for the reference comparison, official sources and known differences.

The SDK locomotion proxy clips are single-pose placeholders that the VRChat client replaces with built-in animations. That client-side locomotion replacement is not implemented here, so these proxies can remain static in the editor while movement parameters change. The simulator does not generate substitute gaits. See the [VRChat proxy animation documentation](https://creators.vrchat.com/avatars/#proxy-animations).

Simulation and audio test sessions restore the values they change when stopped. They create temporary objects outside the avatar and do not add upload components to the avatar. Exiting simulation, pausing, unlinking or losing its camera or temporary floor restores the avatar's position/rotation, motion parameters, prior camera selection and cursor state. The temporary floor is removed with the session; existing scene ground remains unchanged. Grounded follows the actual ground probe, including at startup and while input is suspended. Input is accepted by the focused Game or Scene view, with one game simulation active at a time. Keyboard/mouse control requires Active Input Handling **Input Manager (Old)** or **Both** and the standard **Mouse X / Mouse Y** axes. The package uses a separate namespace, assemblies, asset GUIDs, and `GestureManagerPro/` resource prefix. If both tools remain installed through another installation format, use one active simulator per avatar.

To update, refresh the repository in VCC/ALCOMD and use **Update** for Gesture Manager Pro. Published versions remain available in the same repository. See the validation record for tested configurations and remaining manual checks, including hardware, real avatar scenes and visual layout.

For development, copy the package contents into `Packages/com.vrclearn.gesture-manager-pro`, excluding development tooling. Unity ignores checkout folders ending in `~` unless explicitly resolved as a package. [Releases](https://github.com/VRCLearn/Gesture-Manager-Pro/releases) also provide VPM ZIP, UnityPackage and manifest files. Use one distribution format per project; the UnityPackage requires the Avatars SDK separately.

## Development and validation

The package embeds GM-derived code under `Scripts` and assets under `Resources/GestureManagerPro`. Localization, audio analysis, model statistics, and controlled input have separate assemblies. Editor code uses the included SDK interfaces directly; no localization Harmony patches are installed.

Development automation follows the existing VRCLearn package layout: `.github/scripts` contains publishing scripts, Python distribution tests, and Unity validation runners. `.github/scripts/build_package.py` creates validated, deterministic VPM ZIP and UnityPackage archives, preserving the native library and license notices. `.github/scripts/Build-Package.ps1` invokes the same builder and requires Python 3.10 or later on `PATH`. See the [validation tools](https://github.com/VRCLearn/Gesture-Manager-Pro/blob/main/.github/docs/VALIDATION-TOOLS.md), [validation record](https://github.com/VRCLearn/Gesture-Manager-Pro/blob/main/.github/docs/VALIDATION.md), and [publishing conventions](https://github.com/VRCLearn/Gesture-Manager-Pro/blob/main/.github/docs/PUBLISHING.md). Development files, temporary validation projects, build output, and Unity-ignored names are excluded from archives along with their metadata. VPM ZIPs retain explicit directory entries so empty asset folders and their `.meta` files survive extraction together. The published `package.json` identifies the source repository and exact commit through `repository.url`, `repository.revision`, and `sourceRevision`.

The project does not claim to reproduce all VRChat client behavior. Game Simulation is a local testing controller; SDK proxy replacement, AngularY scaling, networking and client audio processing remain unsupported or unverified. VR input, calibration, body IK and local head clipping have an independent implementation with specific remaining differences documented in [VR-SIMULATION.md](VR-SIMULATION.md). Review localized glyph rendering and long-label layout on the target operating system and display scale, and test physical keyboard/mouse focus transitions, microphones, VR hardware and real avatars before treating this development build as stable.

Android shader restrictions follow the SDK's exact shader names rather than `Shader.isSupported` or a name-prefix rule. Pink materials are an editor diagnostic: the SDK rejects unsupported shaders during upload, so this appearance is not a claim about their rendering in a VRChat client. The separate `Toon Standard (Outline)` to `Toon Standard` conversion follows the documented [mobile shader behavior](https://creators.vrchat.com/platforms/android/quest-content-limitations/#shaders). This tool does not reproduce the client's general Safety System shader fallbacks or mobile GPU lighting and quality settings.

## Upstream and licenses

The Inspector's **About and Contributors** section displays a GitHub contributor snapshot refreshed during release preparation, including contributors from the preserved upstream history. Names and profile links are included as a small local JSON resource. Avatar images load only when the section is expanded, with up to three concurrent requests; downloaded textures are reused for that Inspector's lifetime and released when it closes. Folding the section or leaving settings cancels pending requests. Names and links remain available without a network connection. Images are not included in either installation archive. Required copyright and permission notices are retained in the license files below.

The GNU AGPL and upstream MIT licenses do not cover that native library; the linking permission does not replace Meta's terms.

## Packaging

The canonical VPM index is [index.json](https://vrclearn.github.io/Gesture-Manager-Pro/index.json), hosted on GitHub Pages using the same official VRChat template and VRCLearn banner as the organization's other packages. Numeric stable tags matching `package.json` publish immutable Release assets after distribution tests on Windows, macOS and Linux.
